# 경험 데이터 인출 프로토콜

정리된 자료는 없지만 경험은 있는 상태에서, 상용성 데이터베이스의 초기 데이터셋을
구축하기 위한 절차입니다.

## 전제 — 데이터가 없는 것이 아니라 흩어져 있다

누리에 이미 존재하는 것:

| 소재 | 있는 곳 | 담고 있는 정보 |
|---|---|---|
| 거래명세서 · 세금계산서 | 회계 시스템 | 누구에게 · 언제 · 무엇을 · 얼마나 (세법상 반드시 보존) |
| 발주서 · 견적서 | 영업 파일 | 수지 · 규격 · 제조사 · 수량 |
| 카톡 · 메일 이력 | 담당자 단말 | 클레임 정황, 고객이 보낸 사진 |
| 담당자 기억 | 사람 | **어떤 조합이 터졌는지** — 가장 중요하고 가장 휘발성이 높음 |

거래 이력은 세금계산서 때문에 반드시 남아 있습니다. 빠져 있는 것은
**"그래서 그 건은 어떻게 됐는가"라는 결과 라벨**뿐이며, 그것이 담당자 머릿속에 있습니다.

따라서 작업은 신규 조사가 아니라 **결합**입니다.

```
거래 이력 (있음)  +  결과 라벨 (기억)  =  초기 데이터셋
```

## 1단계 — 실패 인출 세션 (2시간, 1회)

영업·CS 담당자를 모아 진행합니다. 혼자 하지 마십시오. 한 사람이 잊은 건을
다른 사람이 기억하고, 그 과정에서 세부가 복원됩니다.

### 진행 순서

1. **자유 회상 (30분)** — "지금까지 클레임 났던 건을 그냥 다 말해 보십시오."
   이 단계에서는 기록하지 말고 목록만 만듭니다. 판단·평가 금지.
   평가가 들어가면 사람들이 말을 아끼기 시작합니다.

2. **건별 상세화 (60분)** — 목록의 각 건을 도구의 입력 폼으로 채웁니다.
   기억나지 않는 항목은 반드시 **불명**으로 두십시오. 추측해서 채우면
   데이터가 오염되고, 나중에 어느 값이 추측인지 구분할 수 없게 됩니다.

3. **거래 이력 대조 (30분)** — 회계·영업 자료에서 해당 건을 찾아
   시기·수지·제조사·수량을 정확한 값으로 교정합니다.
   `근거` 필드를 **기억**에서 **기록**으로 올립니다.

### 기억을 되살리는 질문

기억은 "언제"보다 "사건"으로 인출됩니다. 이렇게 물으십시오.

- 반품을 받은 건은?
- 고객이 사진을 보내온 건은?
- 재납품해 준 건은?
- 거래가 끊긴 고객이 있다면 마지막 건은 무엇이었나?
- 여름에 터진 건, 수출 나간 뒤 터진 건은?
- "그 제조사 물건은 조심하라"고 서로 말하던 것이 있나?

마지막 질문이 가장 값집니다. 그런 경고는 이미 여러 번의 실패에서 만들어진
집단 학습이고, 아직 문장으로만 존재하는 데이터입니다.

## 2단계 — 정상 건 소급 입력 (핵심)

**이 단계를 건너뛰면 데이터베이스가 작동하지 않습니다.**

실패만 모으면 나오는 결론은 하나뿐입니다 — "전부 위험하다".
실패율을 계산하려면 분모가 필요하고, 분모는 문제 없이 나간 건들입니다.

### 방법

거래명세서에서 **최근 2년치 납품 건**을 뽑아, 클레임 목록에 없는 건은
전부 `결과 = 정상`으로 입력합니다. 개별 확인은 불필요합니다.
클레임이 안 들어왔다는 것 자체가 정상의 근거입니다.

전 건이 부담스러우면 매출 상위 고객부터 시작하되, **표본을 임의로 고르지 마십시오.**
"기억나는 것만" 넣으면 기억 편향이 그대로 데이터에 들어갑니다.
기간이나 고객 기준으로 자르고, 그 안에서는 전 건을 넣는 방식이어야 합니다.

## 3단계 — 신규 건 상시 기록

이후 모든 납품에 대해 출고 시점에 한 건씩 입력합니다.
클레임이 들어오면 해당 건의 `결과`만 수정합니다.

출고 시점 입력이 중요한 이유는, 그때는 수지·제조사·로트·경로가
모두 손 안에 있기 때문입니다. 클레임이 들어온 뒤에는 다시 찾아야 합니다.

## 데이터 품질 규칙

1. **추측 금지.** 모르면 불명. 불명은 결측이지 오답이 아닙니다.
2. **`근거` 필드를 반드시 구분.** 기억 / 기록 / 시험은 신뢰도가 다릅니다.
   나중에 기억 기반 건만 골라 검증할 수 있어야 합니다.
3. **정상 건도 입력.** 분모 없이는 아무것도 계산되지 않습니다.
4. **향료는 계열까지.** "향료 있음"과 "시트러스·리모넨"은 완전히 다른 데이터입니다.
   리모넨의 확산계수는 라벤더유의 약 5배이고, 그만큼 수명이 짧아집니다.
   이 한 칸이 경쟁사가 가지지 못한 예측력의 출처입니다.
5. **CSV로 정기 백업.** 도구는 브라우저 저장소를 씁니다.
   브라우저 데이터를 지우면 이력도 사라집니다.

## 판정 기준

| 근거 건수 | 상태 | 사용 범위 |
|---|---|---|
| n < 3 | 참고 | 내부 판단만. 고객 자료 사용 금지 |
| 3 ≤ n < 10 | 잠정 | 내부 경고 · 가혹시험 권고 근거 |
| n ≥ 10 | 안정 | 고객 제시 가능 |

실패율 30% 이상은 고위험, 10~30%는 주의, 10% 미만은 양호로 표시됩니다.

## 목표 수량

| 시점 | 누적 건수 | 도달 상태 |
|---|---|---|
| 1주 | 30~60 | 인출 세션 결과. 주요 실패 유형 파악 |
| 1개월 | 200~400 | 정상 건 소급 완료. 주력 수지 칸이 잠정 판정 |
| 6개월 | 600+ | 주요 조합이 안정 판정. 고객 제시 가능 |

600건은 큰 수가 아닙니다. 2년치 거래명세서를 옮기면 대부분 채워집니다.

## 도구

`tools/compat-db.html` — 브라우저에서 파일을 직접 열면 됩니다.
설치·서버·계정 불필요, 데이터는 외부로 나가지 않습니다.

건수가 수백을 넘어가고 여러 사람이 동시에 입력해야 하면
스프레드시트나 사내 DB로 이관하십시오. CSV 내보내기가 그 이관 경로입니다.
